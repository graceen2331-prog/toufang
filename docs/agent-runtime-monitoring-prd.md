# 产品需求文档：Agent 运行监测增强

**版本**：1.0  
**日期**：2026-08-31  
**质量评分**：94/100

---

## 执行摘要

当前「AI 运行监控」已能展示工作流状态、步骤、成本和 Token，但监测对象以 `workflow_runs` 为中心，同步执行的 Agent、模型内部重试、结构修复、失败模型请求和 Worker/队列健康仍不可见。出现慢调用、连续失败或成本异常时，管理员无法快速判断问题发生在排队、业务步骤、Agent 编排还是模型 Provider。

本次增强将运行追踪统一为“工作流 → 步骤 → Agent → 模型调用”四层结构，覆盖工作流内与同步执行的全部 Agent。第一版提供实时总览、逐次模型调用明细、异常识别、基础队列与 Worker 健康，并在敏感输入输出上实行默认脱敏、管理员显式查看和审计留痕。

---

## 问题与目标

### 当前问题

- 同步 `AgentRun` 未进入工作流列表，运行记录不完整。
- `ai_usage_events` 只记录成功返回的模型请求，失败尝试不可追踪。
- 首次调用、Provider 重试和结构修复无法可靠区分。
- 缺少成功率、失败率、P95 时延、慢调用、卡死运行和成本趋势。
- BullMQ 队列积压与 Worker 在线状态不可见。
- 详情页直接展示输入输出，缺少脱敏、细粒度权限和查看审计。

### 产品目标

1. 管理员能在 3 分钟内定位一次 Agent 失败或慢调用所处层级。
2. 所有通过 `runAgent` 发起的运行均可查询，覆盖率达到 100%。
3. 每一次 Provider 调用尝试都有状态、时延、Token、成本或失败原因记录。
4. 对超时、连续失败、队列积压和预算阈值形成可见告警。
5. 敏感输入输出默认不暴露，完整查看行为可审计。

### 成功指标

- Agent 运行采集覆盖率：100%。
- 模型调用尝试采集覆盖率：100%，包括失败和结构修复。
- 运行中数据刷新延迟：不超过 5 秒。
- 监控聚合 API P95：数据量 10 万条以内不超过 500ms。
- 完整输入输出查看审计覆盖率：100%。

## 用户与权限

### 主要用户：管理员

- 查看跨业务域的运行健康、成本和队列状态。
- 下钻模型调用、错误信息及脱敏后的输入输出。
- 通过专用权限显式查看完整内容，操作写入审计日志。

### 次要用户：市场总监与市场经理

- 查看其现有 `ai:monitor` 权限范围内的运行、聚合指标和脱敏内容。
- 不允许查看完整 Prompt、输入与输出。

### 1. 查看统一运行总览

作为管理员，我希望看到全部 Agent 的实时健康与成本，以便发现异常。

- [x] 展示活跃运行、24 小时调用数、成功率、失败率、P95 时延、今日成本和月预算使用率。
- [x] 展示最近 24 小时的调用与失败趋势。
- [x] 数据按当前租户隔离。
- [x] 运行中页面每 5 秒自动刷新。

### 2. 查询全部 Agent 运行

作为管理员，我希望统一查询工作流内和同步 Agent，以免遗漏故障。

- [x] 支持时间、状态、Agent、Provider、模型、运行模式和异常类型筛选。
- [x] 列表展示状态、业务关联、模型、时长、Token、成本、发起人与异常摘要。
- [x] 同步运行进入独立 Agent 详情；工作流运行可跳转关联工作流。
- [x] 支持游标分页，默认按创建时间倒序。

### 3. 下钻单次运行

作为管理员，我希望查看完整时间线和逐次模型调用，以便定位问题。

- [x] 时间线包含 Agent 创建、模型调用、Provider 重试、结构修复、完成或失败。
- [x] 每次模型调用展示调用类型、序号、Provider、模型、状态、时延、Token、成本和错误。
- [x] 展示关联工作流、步骤、业务主体和发起人。
- [x] 失败信息按预算、Provider、限流、结构校验和未知错误分类。

### 4. 安全查看完整内容

作为管理员，我希望在必要时查看完整上下文，同时保留安全审计。

- [x] 普通详情只返回脱敏后的 Prompt、输入与输出。
- [x] 完整内容通过独立 API 获取，要求 `admin:ai_trace` 权限。
- [x] 用户必须主动点击“查看完整内容”。
- [x] 每次查看写入 `audit_logs`，包含 Agent Run ID、查看区域和请求 ID。

### 5. 查看运行基础设施健康

作为管理员，我希望看到 Worker 和队列的基本健康，判断问题是否来自基础设施。

- [x] 展示 workflow-step 与 rag-ingest 队列的等待、活跃、延迟、完成、失败数量。
- [x] 读取已注册 Worker，展示在线、异常和离线状态；不另建影子心跳表。
- [x] 第一版仅提供只读指标，不提供暂停、清空、重放队列等管理操作。

## 功能范围

### 第一阶段

- 统一 Agent Run 列表与详情。
- 新增逐次模型调用追踪。
- 运行健康、趋势、成本和时延聚合。
- 慢调用、卡死、连续失败、预算阈值提示。
- 基础队列与 Worker 健康。
- 默认脱敏、管理员完整查看、审计留痕。
- 保留现有工作流重试与取消能力，不扩大副作用操作范围。

### 第二阶段

- 可配置告警规则与告警静默。
- Slack、邮件等外部告警通道。
- Prompt 版本与模型质量对比。
- 队列暂停、任务重放等高风险运维操作。
- 真正的 Provider 请求中止与协作式取消。

### 明确不在第一阶段

- 存储或展示 API Key、认证头等密钥。
- 对任意同步 Agent 提供无条件重放。
- 用监控页面替代专业日志/APM 平台。
- 质量自动评分与人工标注闭环。

## 技术方案约束

### 数据模型

- `agent_runs` 继续作为一次 Agent 编排的事实表，补充业务关联和最后活动时间。
- 新增 append-only `agent_calls`，记录每次模型调用尝试；成功调用仍写 `ai_usage_events` 作为计费事实。
- 基础设施健康直接读取 BullMQ 队列计数、最老等待任务与已注册 Worker；读取失败时返回降级状态，不另建容易失真的影子心跳表。
- 所有索引必须以租户和常用时间/状态筛选为主，禁止跨租户聚合。

### 分层

- 后端新增 `server/modules/agent-monitor/` 的 repository 与 service。
- API 使用 `/api/v1/agent-runs`、`/api/v1/agent-runs/[id]`、`/api/v1/agent-runs/[id]/sensitive`、`/api/v1/agent-monitor/summary` 和 `/api/v1/agent-monitor/infrastructure`。
- 前端新增 `features/agent-monitor/`，`src/app` 页面只负责装配。
- 工作流详情保留现有路由，通过关联 ID 与 Agent 详情互跳。

### 安全与隐私

- 脱敏覆盖邮箱、手机号、访问令牌、API Key、Cookie、Authorization、联系人与付款相关键名。
- 完整内容只从专用端点按需返回，不进入普通列表、缓存或预取。
- Prompt 模板和消息不得记录 Provider 密钥。
- 监测表遵循项目 append-only 约定；后续通过归档与保留策略控制热数据规模。

### 性能

- 聚合指标基于明确时间窗口与复合索引，不在请求中扫描无界历史。
- 列表采用游标分页；详情按需加载敏感内容。
- BullMQ 指标读取失败时返回降级状态，不阻塞 Agent 运行主链路。
- 追踪写入失败不得覆盖原始业务异常，也不得阻塞 Agent 主流程完成。

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 追踪写入增加模型调用延迟 | 中 | 使用短事务和 append-only 单行写入；监控失败不覆盖业务结果 |
| 原始输入输出包含敏感信息 | 高 | 默认脱敏、独立权限、按需加载、审计留痕 |
| Worker 心跳无法天然按租户区分 | 中 | 系统级 Worker 状态只向管理员展示；队列任务指标按现有队列提供基础视图 |
| 同步 Agent 重试造成重复副作用 | 高 | 第一版不提供通用同步重放，只保留现有工作流重试 |
| 历史数据增大导致聚合变慢 | 中 | 时间窗口、复合索引、后续汇总表与归档策略 |
